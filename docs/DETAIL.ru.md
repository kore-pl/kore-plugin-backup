# kore-plugin-backup

Этот репозиторий реализует плагин резервного копирования для kore (id `backup`). Архивация/восстановление/проверка используют только `archive/tar` + `compress/gzip` Go, чтобы избежать shell-инъекций и различий tar между дистрибутивами. Перенос на внешние носители выполняют сторонние инструменты синхронизации; плагин хранит только ссылки для скачивания и пути хоста.

## Что делает проект

- **Протокол**: `kore.plugin.v1`, `lifecycle=lazy`, `depth_level=production`, полномочие `system:admin`.
- **Методы**: `backup.create` / `list` / `restore` / `delete` / `verify` / `retention` / `stats` / `download` / `jobs` / `schedule.set` / `schedule.get`; принимаются и простые глаголы.
- **Целостность**: проверки `exists` / `size` / `sha256` / `readable` / `entries` сообщаются по отдельности; повреждённые архивы помечаются, никогда не игнорируются.
- **Локальное хранилище**: архивы остаются локально (не S3) и перемещаются внешними инструментами; `download` поддерживает чтение по частям.
- **Наименьшие привилегии**: `info.json.capabilities` — вся поверхность авторизации; записи fail-closed.

## Быстрый старт

```bash
make check    # gofmt → vet → test
make build    # собрать бинарник
make dist     # создать архив
```

Плагин запускается оболочкой kore по требованию; `info.json` объявляет полномочия и `requires_kore`.

## Частые вопросы

**В: Нужен аккаунт?**
Нет. Никаких аккаунтов, онлайн-проверок и скрытой телеметрии; конфигурация — открытый текст.

**В: Где плагины?**
Каждый плагин в своём репозитории `kore-plugin-<id>` и зависит только от `kore/pkg/pluginapi`.

**В: С чего начать?**
Прочитайте протокол и таблицу методов в README, затем полномочия в `info.json`.
